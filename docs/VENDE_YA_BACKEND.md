# Vende ya backend (draft, disabled by default)

This is a **separate direct-purchase domain**: TruePhone buys inventory in Bogotá.
It never creates a marketplace Listing, Order, Wompi payment, Payout or seller settlement.
The marketplace's funds-held, shipping, 24-hour acceptance and payout rules are unchanged.
The feature must remain disabled until the launch checklist below is complete.

## Server rules

- Private spreadsheet `Precios TruePhone`, purchase-price column **G**, is the source.
  Range = purchase price − COP 100,000 through purchase price + COP 50,000.
  Example from the verified sheet: iPhone 11 / 128 GB / COP 705,000 → COP 605,000–755,000.
  No additional percentage deduction. Internal purchase-price/import snapshots are never serialized to sellers.
- Existing catalog model/capacity combinations only; retired models are rejected.
  Eight guided photos required, up to 12 total, using the existing listing slot order.
  Files are private JPEG/PNG/WebP, maximum 4 MiB each, with file-signature and MIME checks.
- Submission freezes the price/range/import snapshot. Missing prices route to manual review.
  A priced quote needs explicit range interest before joining the review queue.
- Review SLA = two **working hours**, Mon–Fri 09:00–18:00 America/Bogota.
  Friday 17:00 → Monday 10:00; weekend → Monday 11:00 deadline.
  No holiday calendar is assumed in this v1; weekdays are the agreed review schedule.
- Firm offers expire at **18:00 Bogotá on the next weekday**. The 18:00 interpretation
  is explicit here for Senior Dev/product/legal review, rather than an implicit midnight expiry.
- Immutable numbered offers carry the exact seller-visible conditions. Revised offers
  supersede the previous version and clear current acceptance; old acceptance remains audit history.
  Exact offer ID/version, ownership, current state, and expiry are checked under a quote row lock.
- Offers say TruePhone is the buyer and are subject to pickup identity/IMEI/Activation Lock/condition checks.
  Upload-time ownership/Activation Lock confirmations are declarations, **not** completed pickup checks.
- Acceptance returns `PENDING_SCHEDULING`, not a reserved date or paid state.
  Payments & Trust owns capacity, pickup, verification, own-name Bre-B and payment approval.
- No live transfers or external email are sent by these actions. Offer issue creates one atomic,
  deduplicated in-app notification, respecting `inAppEnabled`, linking to `/vende-ya?quote=<id>`.
  Front End must implement that deep link before enabling the feature.

## Front End contract

Imports: `@/features/buyback/actions/buyback` and
`@/features/buyback/types`. Runtime schemas live in `features/buyback/schemas.ts`.
All actions require a valid Supabase session and `BUYBACK_ENABLED=true`.
Roles are read from Prisma Profile, never user-editable auth metadata.

```ts
// All input/response types are exported from features/buyback/types.ts.
// BuybackDraftInput requires a UUID clientRequestId, catalog model/storage IDs,
// Condition, batteryHealth 0..100, description 10..2000 chars, city:"Bogotá",
// ownershipConfirmed:true and activationLockOff:true.
// BuybackQuoteVersionInput = {quoteId:string; expectedVersion:number}.
// BuybackAcceptInput = {quoteId:string; offerId:string;
//   expectedOfferVersion:number; conditionsAccepted:true}.
// BuybackOfferInput adds amountCop to BuybackQuoteVersionInput.
declare function createBuybackQuoteAction(
  input: BuybackDraftInput,
): Promise<BuybackResult<BuybackQuoteView>>;
declare function getBuybackQuoteAction(
  quoteId: string,
): Promise<BuybackResult<BuybackQuoteView>>;
// FormData: quoteId:string, slot:"0".."11", file:File.
// Owner-only, DRAFT-only. Object paths are generated by the server.
declare function uploadBuybackPhotoAction(
  form: FormData,
): Promise<BuybackResult<BuybackQuoteView>>;
declare function submitBuybackQuoteAction(
  input: BuybackQuoteVersionInput,
): Promise<BuybackResult<BuybackQuoteView>>;
declare function expressBuybackRangeInterestAction(
  input: BuybackQuoteVersionInput,
): Promise<BuybackResult<BuybackQuoteView>>;
declare function acceptBuybackOfferAction(
  input: BuybackAcceptInput,
): Promise<BuybackResult<BuybackQuoteView>>;
declare function cancelBuybackQuoteAction(
  input: BuybackQuoteVersionInput,
): Promise<BuybackResult<BuybackQuoteView>>;
// Owner or ADMIN/REVIEWER. Five-minute bearer URLs; never persist/log/cache.
declare function getBuybackPhotoUrlsAction(
  quoteId: string,
): Promise<BuybackResult<BuybackPhotoUrlView[]>>;
// ADMIN/REVIEWER, cannot review own phone:
declare function sendBuybackOfferAction(
  input: BuybackOfferInput,
): Promise<BuybackResult<BuybackQuoteView>>;
// ADMIN only:
declare function syncBuybackPricesAction(): Promise<
  BuybackResult<BuybackSyncResult>
>;
```

`BuybackResult<T>` is `{ok:true,data:T} | {ok:false,code,error}`.
Typed action inputs are validated again on the server; browser TypeScript is never trusted.
`BuybackQuoteView` is the authoritative seller-safe DTO (IDs, version/status, phone data,
range, manualReview, reviewStartsAt/reviewDueAt, photo slot numbers, current offer and pickupStatus).
All dates are ISO instants; display them in America/Bogota, never browser-local timezone.
After uploads/mutations replace the local DTO with returned data, including `version`.
Never recalculate pricing, offer expiry, review deadlines, or pickup capacity in the browser.

Error handling:

- `QUOTE_CHANGED`: refetch; retain unsaved form input and ask staff to review fresh data.
- `OFFER_CHANGED`: refetch; show current amount/conditions; require a **new explicit confirmation**.
- `OFFER_EXPIRED`: do not accept or auto-retry. Explain expiry and call range-interest with the current quote version to rejoin review (no auto-accept).
- `INVALID_STATE`: no transition occurred; refetch or contact review staff.
- `UNAUTHENTICATED`: login with a safe return URL.
- `NOT_FOUND`: also used for another seller's quote/photos (no existence leak).
- `FORBIDDEN`, `INVALID_INPUT`, `UPLOAD_FAILED`, `SYNC_FAILED`, `NOT_AVAILABLE`:
  show the supplied Spanish message; no internal provider/DB error is returned.

There is no automatic acceptance when a quote or pickup date changes. Current DTO only
reports pending scheduling; Front End must not invent an available pickup date from it.
Reviewer queue: `/revision/vende-ya`, linked from `/revision`, 25 rows/page, staff only.

## Payments & Trust handoff

Build a stacked draft PR on `feat/vende-ya-backend` (do not duplicate this migration).
Core models: BuybackQuote, BuybackOffer, BuybackPhoto, BuybackEvent.
Quote IDs and `currentOfferVersion` connect the purchase case to its exact accepted terms.

Every payment/custody/final-price write must acquire the same quote lock:

```sql
SELECT id FROM buyback_quotes WHERE id = $1 FOR UPDATE;
```

Under that lock re-read status/currentOfferVersion and the current offer, verify
`status=OFFER_ACCEPTED`, `acceptedAt IS NOT NULL`, `supersededAt IS NULL`, and the expected
accepted offer ID/version. **An accepted offer is a recorded agreement, not an unaccepted
quote still subject to its accept-by deadline.** Any changed inspection price needs a new
numbered offer and fresh acceptance. Payment must atomically set quote `PURCHASED` and
increment `version`, record the checks/approval/transfer evidence and append an audit event.
`PURCHASED` is terminal to backend offer/cancel actions.

Payments & Trust must enforce one purchase/day globally with a database uniqueness guard,
reserve/confirm the pickup date before promising it, and invalidate/reconfirm scheduling
when an offer revision changes accepted terms. Lock order should be quote first, then
capacity. `earliestPickupDay` is only a cutoff helper: before 15:00 weekday candidate today,
at/after cutoff next weekday; it does **not** reserve capacity. No marketplace money tables
or automatic Wompi calls belong in this direct-purchase flow.
