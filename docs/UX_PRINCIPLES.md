# TruePhone User Experience Constitution

Version 1.0

---

# Purpose

This document defines the user experience principles that every screen, feature, interaction, animation, and workflow must follow.

These principles are non-negotiable.

Every engineer, designer, product manager, and AI coding assistant working on TruePhone must follow them.

When a design decision conflicts with these principles, these principles take priority.

---

# Principle 1

## Trust Comes Before Speed

The fastest experience is not always the best experience.

Users should always understand:

• What is happening

• Why it is happening

• What happens next

Never sacrifice clarity for speed.

---

# Principle 2

## No Dead Ends

Every page must provide a meaningful next action.

The user should never reach a screen and wonder:

"What do I do now?"

Every screen must contain:

Primary Action

or

Secondary Action

Examples

No Favorites

↓

Browse Listings

No Messages

↓

Browse Listings

No Orders

↓

Explore Marketplace

Listing Rejected

↓

Edit Listing

---

# Principle 3

## Every Page Has States

Every page must define four UI states.

Loading

Empty

Error

Success

No exceptions.

---

Loading State

Use skeleton loaders.

Avoid spinners whenever possible.

Loading should feel intentional.

---

Empty State

Every empty state should:

Explain why it is empty.

Suggest the next action.

Include an illustration when appropriate.

---

Error State

Every error should explain:

What happened

Why

How to recover

Never expose technical information.

---

Success State

Every successful action should provide immediate confirmation.

Examples

Listing submitted.

Profile updated.

Message sent.

Purchase completed.

---

# Principle 4

## Every Action Has Feedback

Users should never wonder if something happened.

Buttons should immediately respond.

Forms should validate immediately.

Uploads should show progress.

Messages should appear instantly.

---

# Principle 5

## Reduce Cognitive Load

Do not overwhelm users.

Break large tasks into smaller ones.

Prefer

5 steps

instead of

1 page with 50 fields.

---

# Principle 6

## Progressive Disclosure

Show information only when needed.

Begin with essentials.

Reveal advanced options later.

The interface should feel lightweight.

---

# Principle 7

## Forms Should Feel Intelligent

Forms should help users.

Never fight them.

---

Requirements

Auto focus

Inline validation

Helpful examples

Auto formatting

Smart defaults

Draft saving

Field grouping

Logical order

---

Never clear a completed form because of one validation error.

---

# Principle 8

## Auto Save Whenever Possible

Large forms should automatically save progress.

Examples

Create Listing

Profile Editing

Draft Description

Messages

Users should never lose work.

---

# Principle 9

## Never Lose User Data

Unexpected refresh.

Browser closes.

Internet disconnects.

Application crashes.

User returns.

Progress should still exist whenever technically possible.

---

# Principle 10

## Every Click Has Purpose

Every button must answer:

Why does this exist?

Buttons without clear value should be removed.

---

# Principle 11

## Beautiful Defaults

Default choices should be the safest choices.

Examples

Safe privacy settings.

Recommended filters.

Helpful sorting.

Clear language.

---

# Principle 12

## Consistency Beats Creativity

A button should always behave like a button.

Cards should always behave like cards.

Navigation should always feel familiar.

Users should never relearn interactions.

---

# Principle 13

## Eliminate Surprises

Unexpected behavior reduces trust.

Prices

Fees

Shipping

Status

Payments

Everything should be transparent.

---

# Principle 14

## Explain Before Asking

Never ask users for information without explaining why.

Examples

IMEI

"We use this to verify the device."

Battery Health

"This helps buyers understand battery condition."

---

# Principle 15

## The Interface Should Feel Calm

Avoid visual noise.

Use whitespace generously.

Avoid unnecessary animations.

Avoid excessive colors.

Avoid unnecessary icons.

Every screen should breathe.

---

# Principle 16

## Trust Is Visible

Trust should be reinforced visually.

Examples

Verified Seller

Buyer Protection

Manual Review Badge

Listing Approved

Secure Checkout

These should appear naturally throughout the experience.

---

# Principle 17

## Design for Confidence

Every interaction should reduce uncertainty.

Buying a used iPhone should feel predictable.

Not risky.

---

# Principle 18

## Error Prevention Is Better Than Error Messages

Prevent mistakes before they happen.

Examples

Disable impossible actions.

Validate early.

Suggest corrections.

Warn before destructive actions.

---

# Principle 19

## Confirmation Before Destruction

Deleting

Removing

Cancelling

Archiving

Large edits

Should require confirmation.

---

# Principle 20

## Mobile First

Every feature should work beautifully on mobile.

Desktop adds space.

It should not add functionality.

---

# Principle 21

## Accessibility Is Part of Good Design

Keyboard support.

Visible focus.

Readable fonts.

High contrast.

Screen reader compatibility.

Accessible forms.

Reduced motion.

---

# Principle 22

## Search Should Be Effortless

Users should find devices quickly.

Search should tolerate:

Typos

Partial words

Different capitalization

Minor spelling mistakes

---

# Principle 23

## Every Screen Should Build Trust

Ask before shipping any page:

Does this increase confidence?

If not—

redesign it.

---

# Principle 24

## Premium Doesn't Mean Complicated

Premium means:

Simple.

Fast.

Elegant.

Thoughtful.

Not overloaded.

---

# Principle 25

## Every Millisecond Matters

Users notice delays.

Optimize everything.

Loading should feel instant.

Interactions should feel immediate.

---

# Principle 26

## Human Review Is the Hero

Most marketplaces celebrate volume.

TruePhone celebrates quality.

The interface should constantly remind users that:

Every listing was manually reviewed.

That is our competitive advantage.

Do not hide it.

Celebrate it.

---

# Principle 27

## Every Feature Must Support the Brand

Before implementing any feature ask:

Does this make TruePhone feel more trustworthy?

Would Apple ship this?

Would Swappa approve this?

Would this reduce uncertainty?

If not—

reconsider the feature.

---

# Principle 28

## Simplicity Is a Feature

The best interface is the one that requires the least explanation.

Users should instinctively know what to do next.

---

# Final Principle

Everything in TruePhone exists to achieve one goal:

People should feel safer buying a used iPhone here than anywhere else.

Trust is not one feature.

Trust is the entire experience.
